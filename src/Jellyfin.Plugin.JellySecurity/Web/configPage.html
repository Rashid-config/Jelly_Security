API scan watch

                            
Counts requests to enumeration endpoints (/Users, /Items, /System/Info, /Library, and similar collection routes) per address, before a scanner ever reaches the sign-in form. Playback, posters, downloads, and static files are never counted. The main signal is failed requests — a scanner without a valid token collects 401s; a real client gets 2xx. Admin, monitoring, and trusted networks are never rate-limited.

                            

                                
                                
Records a Reconnaissance event and incident when one address floods enumeration endpoints with failed or unauthenticated requests across many paths.

Generate rate-limiting rules for your reverse proxy (Nginx, Caddy, or Cloudflare). This is an addition to your existing setup, not a replacement — your domain, certificates, and playback config stay untouched.

                        

                            
What this tab does

                            
This tab builds text you can paste into your reverse proxy (Nginx, Caddy, or Cloudflare) so that sign-in guessing is slowed or blocked before it reaches Jellyfin. The plugin does not edit those systems — it only produces the text. You paste it yourself and reload the proxy.

                            
This is additive. The snippet only adds rate-limiting to sign-in routes. It does not touch your domain, SSL certificates, playback proxy_pass, or any other existing configuration. Back up your proxy config before pasting, so you can restore if something goes wrong.

                            
Two features live here:

                            
    
                                
  1. Snippet — a ready-to-paste rate-limit rule. Turn it on, pick your proxy, set how many sign-in attempts per minute per address, save, then copy and paste into your existing config.
    2. 
                                
  2. Block-list channel — an endpoint your proxy can read to stay in sync with the addresses this plugin has blocked. The proxy authenticates with a shared key.

Alerts

                            
When the plugin detects a pattern (brute force, spray, enumeration, honeypot hit), it records an incident. The options below control how often it records the same incident and whether it also sends it to a webhook.

                            

                                
                                
                                
When the same detector fires for the same target, the plugin waits this many minutes before recording another incident. This prevents alert flooding.

                            

                            

                                
                                
When an incident is recorded, the plugin sends a JSON payload to this URL. The webhook is optional and a failed delivery never blocks sign-in. The URL is validated against SSRF (loopback, private, and link-local addresses are rejected).

                            

                            

                                

                                    
                                    
                                    
HTTPS is preferred. HTTP is allowed for local setups. Private, loopback, and link-local addresses are rejected. Hostnames are DNS-resolved and must resolve to public IPs.
